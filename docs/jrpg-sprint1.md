# Sprint 1 — Walkable Guild implementation

Branch: feature/pharmacy-guild-jrpg. The archived DOS checkpoint is unchanged.

## Implemented source
- jrpg-walk/ is a separate Phaser 3.90 + TypeScript + Vite app, built into frontend/jrpg/walk/.
- Phaser Boot → Guild → Encounter scenes.
- Original 16×16 pixel textures drawn in code for four-direction, three-frame walking hero, Guild Master NPC and local environment.
- Deterministic 24×16 grid map, obstacles, pathing, camera follow and collisions. Player spawns one step from the GM interaction radius.
- Keyboard arrows/WASD, E/Enter/Space; tap-and-hold mobile D-pad and Explore button. Narrow responsive layout and descriptive HTML.
- GM dialogue, scene transition to a fictional battle, existing JRPG S/O/A/P combat engine with a fictional clinical decision and a return to the Guild.
- No login needed for the isolated demo, and no Firebase/Worker/D1 requests or writes. Training rewards are display-only.
- Test coverage: Node map and combat tests; Playwright Chromium desktop + Android touch emulation on a real rendered Phaser page.

## Build
GitHub Actions runs npm ci for the existing project, then npm install --prefix jrpg-walk, npm run build --prefix jrpg-walk, and browser tests. This generates frontend/jrpg/walk/index.html and bundled assets. npm run build from jrpg-walk also generates output.

Production Cloudflare Pages currently serves frontend/ unchanged and does not automatically build the new independent app. To preview this branch, build it in CI or a separate Pages preview with:
- Install + build command: npm install --prefix jrpg-walk --no-audit --no-fund && npm run build --prefix jrpg-walk
- Output directory: frontend
- Game route: /jrpg/walk/
- Do not change the existing production Pages deployment or domain settings.

The separate jrpg-walk/package-lock.json is generated by npm install in CI and not yet committed; pin exact package versions in package.json for the prototype. Commit a reviewed lockfile before production promotion. GitHub Actions uploads the generated static output as an artifact for review.

## Known limits
- Guild uses code-native temporary maps and sprites, not a full external tilemap or sprite sheet.
- NPC and portal have one training encounter, not advanced quest/NPC branching.
- Battle UI reuses the existing fictional JRPG engine. It is not official teaching validation, reward issuing, or a clinical grade.
- Demo resets on reload. There is no authenticated party, cloud save, official inventory, cinematic map, audio or offline service worker.
- Android is tested via Chromium mobile device emulation, not a physical Android device.
- Preview login Firebase domains/Worker CORS remain to be configured when the authenticated portion is tested.

## Branch preview auto-publication

This repository already has **Cloudflare Pages Git integration**, which provides an isolated
`feature-pharmacy-guild-jrpg` branch preview. The earlier Pages deployment succeeded, but
the build output was only a GitHub Actions artifact and **was not committed**; therefore
`/jrpg/walk/` could not yet load from that deployment.

The `JRPG Sprint 1 checks` workflow now runs type checks, all legacy tests, Playwright
desktop/mobile emulation, and compiles Vite assets. **Only on a successful push to
`feature/pharmacy-guild-jrpg`**, a separate least-privilege job commits the checked
`frontend/jrpg/walk/index.html` and `assets/` into **that same feature branch**.
Cloudflare then sees the compiled route and deploys the branch preview. Build commits
skip the publish workflow to avoid a loop. This requires GitHub Actions permission to
push to the feature branch. A failure should be reported, not bypassed by a production merge.

The **confirmed Cloudflare Pages branch preview root** from GitHub's Cloudflare check is
`https://feature-pharmacy-guild-jrpg.pharmacy-guild-web-dev.pages.dev/`.
The playable test path is `/jrpg/walk/` after the generated-asset commit has itself
received a successful **Cloudflare Pages** check. Do not claim the route is live before that.

The preview is deliberately **unauthenticated/demo only**. Firebase login embedded in the
root page remains protected by its existing authorized-domain and Worker-CORS settings;
do **not** weaken CORS globally or point the preview at production D1.

Security note: the generated Phaser bundle is static/public and must remain free of
Firebase ID tokens, clinical records, private student data or Cloudflare credentials.
